Behind the Build

How I Built This

This website is my CSIT 212 Final Project — a personal World Travel Archive documenting every country I have visited since my first overseas trip to Thailand in 2012.

The entire site was built in a single session in collaboration with Claude (Anthropic AI). The rule I set from the beginning: I would write zero lines of code. Every file, every function, every design decision would come from describing what I wanted in plain language and having the AI generate it.

This page is a complete record of that process — every prompt I sent, what the AI did with it, and what I learned about working with AI as a creative and technical partner.

Technology Stack

What This Site Is Built With

HTML5 CSS3 (Custom — no framework) Vanilla JavaScript (ES6+) Google Fonts GitHub Pages (Hosting) Claude AI — claude-sonnet-4-6

No React. No npm. No build pipeline. Just three plain files — HTML, CSS, JavaScript — that any browser can open without installation. This keeps the site fast, maintainable, and deployable anywhere for free. GitHub Pages serves it directly from the repository root.

All travel data lives in a single JavaScript array in main.js. Adding a new trip means adding one object to that array — no database, no CMS, no backend.

19 trips documented 26 countries & territories 5 continents ~282 days abroad 191 photos uploaded 0 lines of code written by hand

The Build Process

From idea to deployed website — each step in order.

Step 01 · Session Start

Defining the Project

I opened Claude Code inside VS Code and described the project: a World Travel Archive website for CSIT 212, deployed on GitHub Pages, where I would write no code myself. I listed four rules: (1) Claude generates everything, (2) the theme is my real travel history, (3) deploy to GitHub Pages, (4) include a "How I Built This" page documenting the full conversation in English.

Claude checked my home directory, identified an existing ~/Projects/ folder, and created the project structure there.

Step 02 · Design System

Visual Identity

Claude designed a dark, editorial aesthetic — inspired by travel magazines and exploration journals. The color palette centers on warm gold (#c8a96e) against near-black backgrounds. Playfair Display was chosen for headings — classical, authoritative — and Inter for body text — clean and highly readable at small sizes.

All styling is in a single custom CSS file (~400 lines). No stylesheet framework was used; every component was written from scratch.

Step 03 · Initial Build (Placeholder Data)

First Version

Claude generated the initial site with six placeholder travel entries (Japan, France, Peru, Morocco, Iceland, Thailand) to establish the data structure and layout. This first version established: the hero section with animated stats counters, the featured cards grid, the country card grid, the timeline view, and the detail page template.

The focus at this stage was getting the architecture right — how data flows from one JavaScript array to every page on the site.

Step 04 · Data Update (Real Travel History)

Replacing Placeholder Data with My Actual Trips

I provided Claude with my complete travel history: 17 trips across 14 years, from Thailand in 2012 to Iceland & Boston in April 2026. For multi-country journeys (Europe 2015, Europe Grand Tour 2024–25, South America 2026), Claude grouped the countries into single trip entries with a combined title and full country list for accurate statistics.

Claude rewrote the entire main.js data array, updated the statistics calculation logic to count unique countries across all trips, and added a single-template detail page system (countries/detail.html?id=...) to avoid creating 17 separate HTML files.

Step 05 · UI Optimization (Filter + Sort)

Year Sorting and Expanded Filters

I asked Claude to optimize the UI so that the archive can be filtered by both region and travel style simultaneously, and sorted by year. Claude restructured the filter bar into two rows (Region / Style), added a sort bar with "Newest First" and "Oldest First" options, and updated the JavaScript filter logic to handle both filtering and DOM-reordering by year simultaneously. A live trip counter updates as filters change.

This required updating css/style.css (new sort bar styles), js/main.js (filter + sort logic), archive.html, and index.html.

Step 06 · This Page

Documenting the Process

I asked Claude to update how-i-built-this.html in full English, with a complete summary of everything that had happened during our session. This page is the result of that prompt.

Step 07 · Deployment

Going Live on GitHub Pages

Claude installed the GitHub CLI (gh) via Homebrew, initiated a browser-based OAuth login flow, and provided a one-time code to authorize. After login, Claude initialized git, created a public repository (geon6398-dot/world-travel-archive), pushed all files, and enabled GitHub Pages via the API.

The site went live at https://geon6398-dot.github.io/world-travel-archive/ within two minutes of pushing.

Step 08 · Design Polish

Hero Background & Typography Tweaks

After seeing the deployed site, I asked for a more adventurous hero background and larger description text. Claude replaced the plain radial gradient with a layered system: floating star-field dots, a shifting gold/blue shimmer animation, and a slow vertical drift — all pure CSS, no images or libraries. Excerpt font size was increased from 0.875rem to 0.95rem with wider line-height.

Step 09 · Real Photos (160 shots)

Adding Actual Travel Photography

I asked Claude to add real photos from my Mac Photos app. Claude created per-trip subfolders inside images/ and opened them in Finder so I could drag photos directly from the Photos app. After I added 160 photos across 12 trips, Claude updated main.js with a travelPhotos lookup object, rewrote createCard() to show real photo thumbnails, updated the featured section to use photo backgrounds, and added a full gallery + lightbox to every detail page — click any photo for full-screen view, navigate with arrow keys, close with ESC.

Step 10 · Data Refinement

Splitting Iceland & Boston into Two Entries

The original "Iceland & Boston" entry was a combined trip. I asked Claude to separate them. Claude split the entry into Iceland (6 days, all the Ring Road / glacier content) and Boston, USA (3 nights / 4 days — Freedom Trail, Harvard, MIT, North End). Each now has its own detail page, story, and highlights list.

Step 11 · Data Refinement

Extracting Qatar from the Europe Grand Tour

Qatar was listed inside the Europe Grand Tour entry as a transit country. I asked Claude to give it its own entry: December 2024, 2 days in Doha. Claude created a standalone Qatar entry (Museum of Islamic Art, Souq Waqif, Doha skyline) and updated the Europe Grand Tour to 8 countries, 43 days.

Step 12 · Photos for New Entries

Qatar & Boston Photography

After creating the Qatar and Boston entries, I asked Claude to open both image folders in Finder. I dragged photos from my Photos app — 9 shots for Qatar, 22 for Boston. Claude detected the new files, added them to the travelPhotos data, and pushed everything to GitHub.

Step 13 · This Update

Keeping the Build Log Current

I asked Claude to confirm the site is publicly visible (it is — anyone with the URL can view it) and to add all recent prompts to this page in English. Claude updated the process steps, conversation log, and project statistics to reflect the current state of the site.

Reflection

What I Learned

The hardest part of building this site wasn't technical — it was knowing what to ask for. Every prompt required me to think clearly about what I actually wanted before I could describe it. The AI handled the syntax; the product thinking was still mine.

This project made a real argument for "plain HTML/CSS/JS" as a serious choice. No build step, no node_modules, no dependency vulnerabilities. Just files that work in any browser, on any machine, in ten years. For a content-focused personal archive, this is exactly the right stack.

Working with Claude Code also showed me how quickly iteration happens when the gap between idea and implementation is a single sentence. Design decisions that would normally take hours of googling and debugging happened in seconds. The bottleneck is always the human's clarity of thought — not the AI's ability to execute.
